# GameFace

A small browser-based game that uses Amazon Rekognition to detect facial expressions. The game shows an emoji overlay on the live webcam stream and asks the player to mimic the expression. The server sends captured frames to AWS Rekognition and returns whether the detected dominant emotion matches the requested target.

This repository contains a minimal Node.js + Express server and a static client in `public/`.

## Features

- Live webcam stream in the browser
- Dynamic emoji targets (uses GitHub emoji API as a free source)
- Server-side Amazon Rekognition integration (no credentials stored in code)
- Overlay UI with start/restart/exit controls, score tracking, and finish card
- Basic security hardening: CSP and HTTP security headers (server-side)

Descriptions:

	- `index.html`: The single-page UI containing the video overlay, controls and layout.
	- `style.css`: All styles for the game UI, overlay, and finish card.
	- `app.js`: Client-side game logic (camera setup, emoji rotation, API calls to `/api/recognize`, and UI updates).

- `README.md`: Project documentation and instructions (this file).

- `package.json`: Project metadata and dependency declarations. Use `npm install` to populate `node_modules`.
- `.gitignore`: Files and folders to ignore in Git (for example `node_modules/`, `.env`, and other local artifacts).



## Prerequisites

- Node.js (16+ recommended)
- An AWS account with Rekognition permission (or proper IAM role)
- Environment where you can set environment variables (local shell or hosting provider)

## Setup (Local)

1. Clone the repository and install dependencies:

```bash
git clone <repo-url>
cd GameFace
npm install
```

2. Set AWS credentials in environment variables (do NOT commit keys):

- macOS / Linux (example):
```bash
export AWS_ACCESS_KEY_ID="YOUR_KEY_ID"
export AWS_SECRET_ACCESS_KEY="YOUR_SECRET_KEY"
export AWS_REGION="us-east-1"
```

-- Windows PowerShell (recommended):
```powershell
# 1) Install AWS CLI v2 if you don't have it: https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html
# Verify installation:
aws --version

# 2) Configure credentials interactively (stores in %USERPROFILE%\.aws\credentials)
aws configure
# You'll be prompted for:
# AWS Access Key ID [None]: <YOUR_KEY_ID>
# AWS Secret Access Key [None]: <YOUR_SECRET_KEY>
# Default region name [None]: us-east-1
# Default output format [None]: json

# Optional: create a named profile instead of the default
aws configure --profile gameface

# The AWS SDK for JavaScript will pick up credentials from the shared credentials file
# (or from environment variables). To use a named profile for the Node process, set the env var
# for the session (PowerShell):
setx AWS_PROFILE "gameface"
# or for the current session only:
$env:AWS_PROFILE = "gameface"
```

Tip: For local convenience you may use a `.env` file with `dotenv` but ensure `.env` is added to `.gitignore` and never committed. The code is written to use the AWS SDK's default credential chain so environment variables are sufficient.

3. Start the server:

```bash
node server.js
# or use a process manager (pm2) in development
```

4. Open the app in a browser: `http://localhost:3000` (or the port printed by the server).

## How it works (overview)

- The client (`public/app.js`) captures a still frame from the `video` element and sends a data URL to the server endpoint `POST /api/recognize` with a `target` key (emotion target like `happy`, `sad`, etc.).
- The server converts the data URL to bytes and calls AWS Rekognition `DetectFaces` with `Attributes: ['ALL']`.
- The server extracts the top emotion from Rekognition and responds with `{ faceFound, foundEmotion, confidence, matched, expected }`.

## Important: AWS Credentials and Security

- Never hard-code AWS credentials in `server.js` or any code file.
- Use environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and optionally `AWS_SESSION_TOKEN` and `AWS_REGION`). The AWS SDK automatically reads those.
- Prefer running the server on an AWS resource (EC2, ECS, Lambda) with an attached IAM role granting Rekognition permissions so that you don't need long-lived credentials.
- Ensure any CI/CD or hosting provider secrets configuration uses their secure secret store (do not store secrets in the repo).

## Security & Deployment Notes

- The server sets a minimal set of security headers (CSP, X-Frame-Options, etc.) and redirects to HTTPS when `NODE_ENV=production` and behind a proxy that sets `x-forwarded-proto`.
- When publishing to the public web, ensure TLS/HTTPS is enabled by your hosting provider (or use a load balancer / reverse proxy that terminates TLS).
- Maintain a restrictive CSP. The client currently fetches emoji images from GitHub's emoji assets; the CSP in `server.js` allows `https://api.github.com` and `https://github.githubassets.com` for that purpose. Review and tighten before production.

## API

- POST `/api/recognize`
	- Request: `Content-Type: application/json` body `{ image: '<dataURL>', target: '<emotion-key>' }`
	- Response: JSON `{ faceFound: boolean, foundEmotion: string, confidence: number, matched: boolean, expected: string[] }`

## Configurable Values

- `PORT` (defaults to `3000`)
- `AWS_REGION` (default in code: `us-east-1` unless `AWS_REGION` or `AWS_DEFAULT_REGION` is set)
- `NODE_ENV` — set to `production` for HTTPS enforcement and stronger security behavior.

## Troubleshooting

- If the camera does not start: allow camera access in the browser and ensure `https://` is used for getUserMedia on production origins.
- If Rekognition returns errors:
	- Verify environment variables `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_REGION` are set for the process running the server.
	- Check that the IAM principal has `rekognition:DetectFaces` permission.
	- Confirm base64 image size is below service limits; server already limits JSON body to 12MB.
- Check server logs for stack traces; Rekognition SDK will surface SDK/HTTP errors when credentials or region are misconfigured.

## Tests / Quick checks

You can test the recognition endpoint with a prepared JPEG base64 payload.

Example (curl):
```bash
curl -X POST http://localhost:3000/api/recognize \
	-H "Content-Type: application/json" \
	-d '{"image":"data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQ...","target":"happy"}'
```

Replace the base64 content with a valid JPEG base64 string.

## Development notes

- Dynamic emoji sourcing uses GitHub's public emojis endpoint; if offline, the client falls back to a small built-in emoji map.
- The client uses a center-screen `Max Rounds` input that is hidden once the game starts.
- The delay between successful match and next emoji is 2 seconds (configurable in `public/app.js`).

## AWS CDK: Provisioning IAM and credentials (recommended patterns)

This project favors assigning an IAM role to the compute resource (ECS task, EC2 instance, or Lambda) rather than embedding long-lived keys. Below are two patterns and an example CDK stack in `cdk/gameface-stack.ts`.

1) Recommended — Use an IAM Role for the compute resource

- Create an IAM role and attach a minimal policy granting `rekognition:DetectFaces` (and related read-only Rekognition actions).
- Assign that role to your ECS Task Role, EC2 Instance Profile, or Lambda execution role. No access keys are required — AWS will provide temporary credentials to the role.

2) Alternative (less recommended) — Create an IAM User and programmatic keys

- Use this only for specific deployment automation that cannot assume a role.
- If you must create keys, store them securely in AWS Secrets Manager and do not commit them to code or repository.

CDK example (already added): `cdk/gameface-stack.ts`

- The file contains a minimal TypeScript CDK `Stack` that provisions:
	- `GameFaceTaskRole` — role with Rekognition permissions (intended for ECS tasks)
	- `GameFaceDeployUser` — an optional programmatic user
	- `GameFaceDeploySecret` — secrets manager entry storing generated access keys (use with caution)

How to use the CDK example (high level):

```bash
# Install and bootstrap CDK (if you haven't already)
npm install -g aws-cdk
cd cdk
npm install
cdk bootstrap aws://<ACCOUNT_ID>/<REGION>
cdk deploy --require-approval never
```

After deployment:
- If you created a role for ECS, attach it to the task definition as the task role.
- If you created a Secrets Manager secret with keys, retrieve the secret in your CI/CD or runtime to set `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` for processes that need them (again — prefer roles).

Security reminders:
- Avoid committing `cdk.out`, `.env`, or any file containing secrets.
- Rotate keys regularly and prefer IAM roles with least privilege.
